# UI audit — 2026-10-10

The UI was reviewed by navigating the existing application with staff, branch manager, HQ manager and platform operator accounts. Grok automation stayed stopped; changes are local commits.

## Changes

- Styled unclassed links and related-screen navigation with the existing design tokens; aligned mobile search actions and wrapped long summary values.
- Removed API paths, environment variable names, benchmark IDs, competitor implementation references and component names from business headings and guidance. The workflow catalog now explains operational periods and links only to visible menus, without presenting research citation coverage as task completion.
- Renamed the isolated preview organization/branch to `데모 기관` / `데모 주간보호센터`. Session profiles now include authorized branch names/types so staff do not call the administrator-only branch directory.
- Corrected guardian directory reads with tenant and selected-branch scope, masked contact data, pagination and search. Contact updates encrypt phone numbers and preserve the existing number when the field is blank. Removed calls to nonexistent guardian attendance/primary endpoints; linked clients open their existing management screens.
- Fixed PostgreSQL nullable keyword binding in linkage record search and the missing NHIS batch branch parameter.
- Home-visit screens explain unsupported branch types before requesting visit APIs; both `HOME_VISIT` and the legacy `HOME_CARE` alias remain supported.
- Suppressed unauthorized staff requests and branch-manager fee-table requests. Existing backend RBAC is unchanged. Branch managers see an accurate calculator access explanation; HQ calculation remains available. Failed/pending annual fee verification keeps uploads blocked without also claiming the fee table is incomplete.
- Preview write allowlists are unchanged. Unsupported writes return a readable JSON message instead of an HTML error page.

## Verification

- Browser: **532 page/viewport/role combinations** at 390 and 1440 px. No horizontal main-content overflow, escaped cards, default browser-blue links, runtime exceptions, unexpected API failures, development reference paragraphs or loading spinners remained. A missing annual care-plan resource returns the documented 404 and correctly opens a new form; the audit records that separately.
- Interaction checks: **27** checks at 320/390/768 px covering the primary mobile screens, guardian detail/edit, law-modal bounds/focus return and menu search; **6** additional staff-detail tab checks at 390/1440 px passed.
- Frontend: full suite initially executed (500 files / 2928 cases); failures from changed UI expectations and the fee-verification description were resolved. Latest related results across **184 files / 1226 cases all pass**, combining the related run and targeted failure reruns. Vitest ran only through the locked `npm test` wrapper, one process at a time.
- Backend: **29** tests pass across authentication, guardian directory, guardian contact creation and linkage records. Coverage includes scope rejection before reads/writes, cross-branch link exclusion, encrypted phone update, blank-phone preservation and masked responses.
- Frontend production build and backend packaging pass. Packaged classes match compiled classes; server REST/Cursor credentials are absent from compiled frontend assets. Preview data, route drafts and assignments were preserved.

## Reproduce

```bash
.venv/bin/python scripts/check-workspace-ui.py
```

The audit uses local preview credentials from the private `.venv/phone-preview/settings.json`, permits only localhost origins, and writes screenshots/results under `/tmp/ogada-workspace-ui-audit`. `OGADA_UI_AUDIT_BASE` and `OGADA_UI_AUDIT_DIR` can select another local preview and output directory.
