# UI 작업 기준

[기존 디자인 토큰](../src/frontend/src/styles/tokens.css)과 컴포넌트를 사용합니다. 화면 변경은 공통 레이아웃과 기존 역할 분기를 먼저 확인합니다.

- 사이드바 하위 메뉴는 한 줄 위주로 배치합니다. 실제 경로·쿼리에 맞는 메뉴 하나만 활성화하고 앱 셸을 유지해 이동합니다.
- [권한표](CURRENT_STATE.md)의 공용·본사·지점·본인 범위를 표시합니다. 서로 다른 출결 화면 진입점은 **범위 분리**, 직원 개인 화면은 **본인 전용**으로 표시합니다.
- 모바일 메뉴는 접어 본문 공간을 확보합니다. 폼·버튼·긴 텍스트는 본문 안에서 줄바꿈하며 큰 표는 표 컨테이너 안에서 스크롤합니다. 320/390/768/1440 px를 확인합니다.
- 기존 링크·버튼 스타일을 사용합니다. 기본 HTML 링크, 중복 선택, 잘린 제목, 화면 전체의 가로 넘침을 수정합니다.
- 배차 작성·이전 배차 불러오기·저장 초안 진입점을 유지합니다. 날짜·승하차 방향 변경·뒤로 가기는 URL 상태를 따릅니다.
- 법령은 페이지별 버튼·모달로 확인합니다. 모바일 범위·스크롤·키보드 포커스·닫기 후 복귀를 검사합니다.
- 고객 화면에 API 경로·키 변수·내부 추적 ID·경쟁사 조사 설명을 넣지 않습니다. 오류·빈 데이터·조회 중·권한 없음은 구분합니다.

최근 검증은 [UI 점검](qa/UI_AUDIT_2026-10-10.md)에 있습니다. 새 변경은 영향받는 실제 화면·역할·너비를 확인하며 기존 전체 검사 결과를 새 코드의 통과 증거로 재사용하지 않습니다.
