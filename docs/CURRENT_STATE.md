# 현재 구현과 권한

확인 기준: 2026-10-10. 코드 버전은 루트 Git 서브모듈 포인터로 기록합니다. 실제 현재 커밋은 `git submodule status`와 각 저장소의 `git log -1`로 확인합니다.

| 역할 | 코드 | 화면·데이터 범위 |
|---|---|---|
| SaaS 제공자 | `ogada_platform_admin` | 플랫폼 운영·기관 관리. 기관 내부 인사·돌봄 권한과 분리 |
| 본사관리자 | `hq_admin` | 소속 기관과 허용 지점의 통합 운영, 본사 설정 |
| 지점관리자 | `branch_admin` | 배정 지점의 운영·직원 관리·배차 작성 |
| 직원 | `staff` | 허용 지점의 돌봄 업무·확정 송영, 본인 출퇴근 |

사회복지사·요양보호사 역할은 직원으로 정규화합니다. 플랫폼·시스템 관리자 기능은 SaaS 제공자 역할로 통합했고, 기관용 `sysadmin`과 이용자·보호자 로그인 화면은 비활성화했습니다. 보호자 연락처·이용자 연결 기록은 기관 업무로 유지합니다.

| 화면 표시 | 의미 |
|---|---|
| 공용 | 직원도 열 수 있는 업무 화면. 쓰기 권한은 기능별로 다름 |
| 본사·지점 | 본사·지점 관리자 화면 |
| 본사 | 본사관리자 전용 화면 |
| 범위 분리 | 관리자와 직원의 조회 범위·화면이 다름 |
| 본인 전용 | 직원 자신의 근무 정보와 출퇴근 처리 |

최종 인가는 서버 역할과 기관·지점·소유자 검증으로 결정합니다. 본사 조회 권한이 있어도 일부 인사 쓰기는 지점관리자만 가능합니다.

## 주요 동작

- 직원은 **내 근무 → 내 출퇴근**에서 자기 출퇴근만 조회·처리합니다. 관리자는 지점 직원 목록과 근태를 봅니다. 전체 근무표·인사서류·직원 건강검진·연차·급여·관리 일지는 직원 메뉴와 API에서 제한합니다. 이용자 출결·돌봄 기록은 허용된 공동 업무입니다.
- **배차 작성**과 송영표에서 수동 승·하차 배차, 이전 배차 불러오기, 저장 초안 수정, 확정·확정 취소를 제공합니다. 자동 배차 추천은 승차 기준입니다. 본사·지점 관리자는 허용 범위에서 작성하며 직원은 확정 배차만 봅니다. 삭제 API는 본사 전용이고 공개 미리보기에서는 차단됩니다.
- 송영표·배차 날짜와 방향은 URL에 동기화됩니다. 기존 배차와 역할별 주소·연락처 마스킹을 유지합니다.
- 보호자 연락처·검색·연결 이용자 조회에 기관·지점 범위를 적용합니다. 전화는 암호화 저장·마스킹 응답하며 빈 입력은 기존 번호를 보존합니다.
- 관련 법령은 페이지별 버튼으로 모달에서 확인합니다. 주간보호 지점은 방문요양 전용 API를 호출하지 않도록 안내합니다.
