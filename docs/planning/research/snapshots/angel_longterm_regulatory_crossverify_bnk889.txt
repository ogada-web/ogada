## 1. ★★★ SEC-D34 축9/축10 = no-break (U+00A0) + ideographic (U+3000) space [엑셀 포맷 내성 스캔]
================================================================
- 문제: `java.util.regex.Pattern` 의 `\s` character class 는 유니코드 공백 전체를 포함하지 않는다.
  no-break space(U+00A0)·ideographic space(U+3000) 은 `\s` 매치 대상 밖 → 기존
  `.replaceAll("\\s+","")` chain 통과 후에도 잔존 → BigDecimal/Integer parse 실패 → null →
  유효 청구/입금 행 조용히 누락 → 재무 대사 왜곡.
- 발생 시나리오(commit body verbatim):
  · U+00A0 : "CMS/web copy-paste" (은행 웹포털·CMS 편집기·Word 편집 copy&paste)
  · U+3000 : "fullwidth IME alongside the fullwidth digits/comma already handled"
             (한국 IME 전각 모드에서 콤마·숫자와 동일 시점 발생)
- 해결: shared helper `ExcelAmountNormalizer.normalizeNumeric` 에
  `.replace(NO_BREAK_SPACE,"")` + `.replace(IDEOGRAPHIC_SPACE,"")` 을
  기존 `.replaceAll("\\s+","")` **바로 앞** 에 명시 삽입(order-preserving·ASCII behavior-neutral).
  단일 source of truth (BNK-886 refactor) 이므로 NhisExcelParser·BankDepositExcelParser
  두 importer 자동 lockstep(rules §13 코드 재사용 posture 재확인).
